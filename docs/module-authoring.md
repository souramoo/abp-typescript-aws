# Module authoring guide

Application modules under `modules/<name>` port `../abp/modules/<name>`. One package, ABP's layers as subpath exports:

```
modules/identity/
  package.json          exports: ".", "./domain-shared", "./domain", "./application-contracts",
                                 "./application", "./http-api", "./dynamodb"
  src/domain-shared/    constants, enums, ETOs, error codes, localization resource + en.json texts,
                        setting names, module class AbpIdentityDomainSharedModule
  src/domain/           entities (extend AggregateRoot/Entity from @abp/ddd-domain), repository
                        interfaces + tokens, domain services (DomainService), data seed contributors,
                        permission/setting/feature definition providers that belong to the domain,
                        AbpIdentityDomainModule
  src/application-contracts/  DTOs (zod `static schema`), app service interfaces + tokens,
                        permission definition provider + permission name constants,
                        AbpIdentityApplicationContractsModule
  src/application/      app services (extend ApplicationService/CrudAppService), object-mapping profile,
                        AbpIdentityApplicationModule
  src/http-api/         controllers (@Controller/@HttpGet… from @abp/aws-lambda) delegating 1:1 to the
                        app service interface, AbpIdentityHttpApiModule
  src/dynamodb/         IdentityDynamoDbContext (AbpDynamoDbContext), DynamoDB repositories (extend
                        DynamoDbRepository, use usingIndex for lookups), AbpIdentityDynamoDbModule
                        calling addDynamoDbContext(services, IdentityDynamoDbContext, o => o.addDefaultRepositories()...)
  src/index.ts          re-exports every layer (convenience; layer imports stay the rule)
  test/                 vitest: domain + application tests on @abp/memory-db (a MemoryDbContext with the
                        same entities), http-api tests through AbpHttpHost, dynamodb tests with aws-sdk-client-mock
```

Dependency direction (enforced by review): http-api → application-contracts; application → domain + application-contracts;
domain → domain-shared; dynamodb → domain. Never import a sibling layer upward.

## Patterns

- **Entities**: `class IdentityUser extends FullAuditedAggregateRoot<Guid> implements IMultiTenant` with a primary
  constructor enforcing invariants, sub-collections initialised, `tenantId` nullable, id passed in (generated by
  `IGuidGenerator` in the caller). Domain methods for state changes (`setUserName`, `addRole`, …).
- **Repositories**: `export interface IIdentityUserRepository extends IRepository<IdentityUser, Guid> { findByNormalizedUserName(...) ... }` +
  `export const IIdentityUserRepository = createToken<IIdentityUserRepository>("IIdentityUserRepository")`.
  DynamoDB/memory implementations register with `options.addRepository(IdentityUser, IdentityUserDynamoDbRepository)` and are
  additionally exposed under the custom token (`services.addTransient(IIdentityUserRepository, Impl)` in the db module).
- **App services**: `class IdentityUserAppService extends CrudAppService<...> implements IIdentityUserAppService` with
  `static readonly inject = [IIdentityUserRepository, IdentityUserManager, ...] as const`, `@Transient(IIdentityUserAppService)`,
  `@Authorize(IdentityPermissions.Users.Default)` at class level and per-method overrides, exactly as the .NET service.
- **Controllers**: `@Controller("api/identity/users", { remoteServiceName: "AbpIdentity" }) @Transient() class IdentityUserController extends AbpControllerBase`
  with `static readonly inject = [IIdentityUserAppService] as const` and one method per action:
  `@HttpGet(":id", route("id", { type: "guid" })) get(id: Guid) { return this.userAppService.get(id); }`,
  `@HttpGet("", query(GetIdentityUsersInput)) getList(input) {...}`, `@HttpPost("", body(IdentityUserCreateDto)) create(input) {...}`,
  `@HttpPut(":id", route("id", { type: "guid" }), body(IdentityUserUpdateDto)) update(id, input) {...}`.
  Routes and verbs must match the .NET `[HttpGet("{id}")]` attributes so ABP client proxies keep working.
- **Permissions**: `IdentityPermissions` constants + `IdentityPermissionDefinitionProvider extends PermissionDefinitionProvider`
  (`@Transient()`), display names via `localizableString(IdentityResource, "Permission:Users")`.
- **Localization**: `@LocalizationResourceName("AbpIdentity") class IdentityResource {}` + the module's `en.json` texts
  ported into a TS object (`identityEn`), added in the domain-shared module with `options.resources.add(IdentityResource, "en").addJson(identityEn)`.
- **Settings/Features**: definition providers in the domain layer (`IdentitySettingNames`, `IdentitySettingDefinitionProvider`).
- **ETOs & distributed events**: ETO classes in domain-shared with `@EventName("...")`; `AbpDistributedEntityEventOptions.etoMappings.add(Entity, Eto)` in the domain module.
- **Data seeding**: `@Transient() @DataSeedContributor() class IdentityDataSeedContributor` porting the .NET seeder.
- **Caching**: `distributedCacheToken(XCacheItem)` for definition/permission caches; invalidate through distributed events like ABP.
- **Tests**: use `createAbpIntegratedTest(TestModule)` from @abp/test-base with a test module that depends on the module's
  `*DynamoDbModule` replaced by a memory-db context (`addMemoryDbContext(services, XMemoryDbContext, o => o.addDefaultRepositories())`)
  and registers the custom repositories' memory implementations; assert behaviour through app services and HTTP.
