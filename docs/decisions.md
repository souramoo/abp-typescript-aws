# Decision log

| # | Decision | Why |
|---|----------|-----|
| 1 | Legacy TypeScript decorators (`experimentalDecorators`) | TC39 decorators are not transformed by vitest/oxc or esbuild yet; legacy decorators work in tsc, esbuild and oxc. |
| 2 | Tokens (`createToken<T>()`) + `static inject` instead of reflect-metadata | No runtime types in TS; explicit tokens keep DI type-safe without a metadata polyfill. |
| 3 | One package per framework package, one package with subpath exports per module | Keeps ABP's layering visible (`@abp/identity/domain` cannot import `/application`) while keeping package count sane. |
| 4 | DynamoDB single table as the default persistence | Serverless-native, no connection pools in Lambda; ABP's repository contracts are expressed without IQueryable. |
| 5 | Own JWT token endpoint (`@abp/auth-jwt`) instead of porting OpenIddict | ABP Identity remains the user store; a password + refresh_token grant is enough for API clients; Cognito JWTs are also accepted. |
| 6 | Source-exports (`"exports": "./src/index.ts"`) and esbuild bundling | No build step per package for dev/test; Lambda bundles are produced by esbuild from sources. |
| 7 | `ABP__<Section>__<Key>` environment variables are loaded twice: verbatim and with the `ABP__` prefix stripped | The CDK stack names deployment settings `ABP__ConnectionStrings__Default`, `ABP__BlobStoring__Aws__BucketName`, … (a namespace, like `DOTNET_`), while the framework's own section is `Abp:` (`ABP__Auth__Jwt__SigningKey` ≡ `Abp:Auth:Jwt:SigningKey`); loading both spellings makes every documented variable work without a per-package `process.env` fallback. |
| 8 | The template has three startup modules: `TemplateAppModule` (provider-independent), `TemplateAppHostModule` (DynamoDB + AWS providers) and `TemplateAppLocalModule` (memory-db + in-process providers), each in its own file and loaded with `import()` by `App:Database` | `@DependsOn` is static and AWS provider classes register themselves (`@Dependency({ replaceServices: true })`) the moment their module file is imported, so a memory host must never import the AWS module files; the handlers therefore pick the module at runtime (`ABP__App__Database=Memory` runs the real Lambda handlers in tests). |
| 9 | The `Tenants` configuration section is honoured by a data seed contributor (`TemplateAppTenantsDataSeedContributor`) that creates and seeds the listed tenants | With the tenant management module `ITenantStore` is repository-backed (`DefaultTenantStore` and its `Tenants` binding are replaced); seeding the section keeps ABP's `appsettings` shape and gives `pnpm dev` a tenant to try `__tenant` with. |
| 10 | Paged request DTOs default `maxResultCount`/`skipCount` in their zod schema | The .NET DTOs initialise the properties, so `GET /api/app/books` without a query string must work; conventional controllers bind `PagedAndSortedResultRequestDto` directly. |
| 11 | esbuild's postinstall is disabled in `pnpm-workspace.yaml` (`allowBuilds: esbuild: false`) | The postinstall replaces `bin/esbuild` with the native binary, which pnpm's node-based bin shims then fail to run (`pnpm exec esbuild`, used by the CDK `NodejsFunction` bundler); without it esbuild's JS launcher finds the platform binary in `@esbuild/<platform>`. |
| 12 | Background work on Lambda is a scheduled `workers.ts` handler running `OutboxSenderManager`, `InboxProcessManager`, `BackgroundJobWorkerManager` and `IBackgroundWorkerManager.runAllOnce()` once per invocation | Lambda has no long-lived timers; `AbpBackgroundWorkerOptions.startWorkersOnInitialization` is false on Lambda and the EventBridge rule (every minute) replaces the .NET worker timers. Locally (`pnpm dev`) the timers run as in .NET. |
| 13 | Mono-lambda is the default deployment; split functions remain available | A single autoscaling function keeps ABP's "one host process" model (one cold start, one config, one log stream) and the cheapest operations; `createMonoLambdaHandler` dispatches API Gateway, SQS (by queue name), EventBridge and direct-invoke events to the same handlers the split topology uses, so switching is a stack flag, not a code change. |
